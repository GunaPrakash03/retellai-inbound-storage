Retell AI Configuration

Complete Setup Guide — Voice Agent + Real Phone Number (Twilio)
Prepared: July 31, 2026

Overview

This guide covers the complete setup of the AI voice intake agent: configuring the agent itself inside the Retell AI dashboard (Part 1), and, separately, giving it a real phone number that callers can dial by connecting a Twilio number through SIP trunking (Part 2).

Part 2 is only required if you want to accept real phone calls from a public number. It is not needed to test the agent using Retell's built-in browser-based test call feature.

Every step below assumes no prior familiarity with either platform and can be followed in order from a blank setup.

Glossary — terms used in this guide

TermWhat it means
WebhookAn automatic notification the voice platform sends to another system the moment something happens — in this case, the moment a call starts or ends. It's simply a web address that gets a message sent to it automatically, with no one needing to click anything.
Signing keyA secret value used to prove a webhook notification genuinely came from Retell, and wasn't sent by someone else pretending to be Retell. Both sides (Retell and the backend) must use the exact same key for this proof to work.
Post-Call Data ExtractionRetell's built-in feature that reads the finished conversation and pulls out specific pieces of information from it automatically — for example, the caller's name or which type of legal matter it was — without a human needing to listen to the recording.
Selector / Boolean / Text (field types)The three data types used above: Selector = must be one of a fixed list of options; Boolean = a yes/no (true/false) value; Text = free-form written text.
SIP trunkingThe telephony method used to connect a real phone number to an AI system over the internet, instead of over a traditional phone line. Think of it as a virtual phone line between Twilio and Retell.
Termination (in Twilio)The “outbound” side of the phone connection — it's what allows Retell to send call audio out through Twilio's network.
Origination (in Twilio)The “inbound” side of the phone connection — it's what allows an incoming call to a Twilio number to be handed off to Retell.
IP whitelist / Credential ListTwo different ways to prove that only Retell (and not anyone else) is allowed to use your Twilio trunk. An IP whitelist checks where the connection is coming from; a Credential List checks a username and password instead.

Part 1 — Agent Configuration (Retell AI Dashboard)

All steps in this part are performed inside the Retell AI dashboard.

1.1 Configure the Webhook URLs

This tells Retell which web addresses to automatically notify when a call starts and when it ends, so the backend system can record what happened. Without this step, calls would still go through, but nothing would ever be saved anywhere.

  1. Log in to the Retell AI dashboard.
  2. From the agents list, click on the voice agent you're configuring to open its editor screen.
  3. On the right-hand side of the agent editor, find the collapsible panel labeled “Webhook Settings” (it may be collapsed by default — click its heading or the small arrow/chevron next to it to expand it).
  4. Inside that panel, locate the field labeled “Agent Level Webhook URL.”
  5. Click into that field and enter the backend's call-events address, in the form: https://<your-domain>/webhooks/retell — where <your-domain> is the actual public web address of the backend system (ask your engineering team for this if you don't already have it).
  6. Still within the same settings area, find the separate field for the pre-call / inbound webhook. This one fires the instant a call connects, before the agent even speaks, and is used to recognize returning callers. Enter: https://<your-domain>/webhooks/retell/inbound
  7. Below these fields, find “Webhook Events” and confirm the default event types are selected — these are typically labeled call started, call ended, and call analyzed. Leave all three checked; nothing needs to be unchecked.
  8. Click “Save” (usually a button at the top or bottom of the agent editor) to store these settings.

1.2 Connect the Webhook Signing Key

This lets the backend verify that a webhook notification genuinely came from Retell, and wasn't sent by someone else pretending to be Retell. If this key is wrong, every single notification will be silently rejected and no calls will ever be saved, even though the calls themselves work fine.

  1. In the Retell dashboard, find “API Keys” in the main left-hand navigation menu and click it.
  2. You'll see a list of one or more keys. Look specifically for the one that has a small “webhook” badge or label next to it — this is the one and only key Retell uses to sign webhook notifications. If your account has multiple keys and you pick the wrong one, verification will fail even though everything else is set up correctly.
  3. Click to reveal/copy that key's full value. Copy it exactly as shown, including any prefix characters at the start of the key, and make sure no extra space or line break gets included when you paste it later.
  4. Open your backend hosting platform's dashboard (for example, Railway) in a separate browser tab.
  5. Navigate to the backend service, then find its “Variables” (or “Environment Variables”) section.
  6. Find the variable used to store the Retell API key and paste in the value you just copied, replacing whatever was there before.
  7. Save the variable. Most hosting platforms will automatically restart/redeploy the backend service after an environment variable changes — confirm this restart completes before testing.

1.3 Paste the Conversation Script

This is the actual set of instructions that controls everything the AI agent says and does during a call — the greeting, the safety check, which questions it asks, and how it ends the call. The complete script currently in use is included in full in Appendix A at the end of this document.

  1. In the agent editor, find the main script/prompt text box — this is usually the large panel taking up the left or center portion of the screen, and may simply be labeled with the agent's name or a generic “Prompt” label.
  2. Click inside that box, select all of the existing text (for example, using Ctrl+A or Cmd+A), and delete it.
  3. Paste in the complete script from Appendix A, exactly as written, with no lines skipped or reordered.
  4. Check whether there is a separate “Welcome Message” field elsewhere in the agent editor. If there is, and it's meant to hold the very first thing the agent says, make sure it matches the “Opening” line already included at the top of the script — or simply leave it blank if the editor allows the script itself to control the opening line.
  5. Click “Save” to store the script.

1.4 Add the Post-Call Data Extraction Fields

These are the structured pieces of information Retell pulls out of every finished call, by reading the conversation transcript automatically after the call ends — no one has to listen to the recording to fill these in by hand. Each one must be added with a matching name, type, and description, or the backend won't recognize it.

  1. In the agent editor, find the “Post-Call Data Extraction” (sometimes labeled “Post Call Data Retrieval”) panel — this is usually a separate collapsible section from the main script box.
  2. Click the “+ Add” button once for each field listed in the table below (14 fields total).
  3. For each one you add, a small form appears asking for a Field Name, a Type (chosen from a dropdown), and a Description. Set the Field Name and Type exactly as shown in the table, and paste in the matching Description text exactly as written — Retell uses this description to decide what counts as a match when reading the transcript, so re-wording it can change what gets extracted.
  4. Repeat for all 14 rows below before moving on.
Field NameTypeDescription
case_categorySelectorOne of: personal_injury, workplace_employment, medical_product, family_law, criminal_defense, immigration, real_estate_housing, business_contract, estate_disability, other
caller_nameTextFull name of the caller
callback_phoneTextBest callback number, digits only
emailTextCaller's email address
incident_dateTextDate of the incident/arrest/deadline in YYYY-MM-DD if determinable

  1. Leave the default fields already present — Call Summary, Call Successful, User Sentiment — in place; do not remove them.
  2. Save your changes.

Why these particular fields matter

  • case_category is what lets every call be sorted by the type of legal matter it is, so an immigration case doesn't get mixed in with a personal injury case.
  • emergency_flagged is what separates a genuine safety escalation from a normal call — a call with this set to true is treated as a priority regardless of what else is or isn't filled in.
  • key_date_or_deadline exists because different matters have different kinds of important dates (a court date, an arraignment, a filing deadline) — this single field holds whichever one applies, so staff always know where to look for it.
  • additional_details is a deliberate catch-all — it exists so the agent always has somewhere to put category-specific information that doesn't cleanly fit any other field, rather than forcing it into the wrong place or losing it.

1.5 Verify the Connection

This confirms the previous four steps actually work together end to end before relying on the agent for real calls.

  1. In the agent editor, find the “Run Test” (sometimes labeled “Test Audio” or shown as a play/microphone icon) button, usually near the top-right of the screen.
  2. Click it to start a trial call, then speak with the agent as if you were a real caller — answer the safety check, describe a sample situation, and provide a name, phone number, and email so there's real data to check afterward.
  3. Let the call run all the way through to the closing readback and thank-you line, then end it.
  4. Check the backend's stored records (ask engineering for the relevant dashboard or endpoint if you don't have direct access) to confirm the test call appears, with the fields you spoke filled in correctly.
  5. If the test call fails outright with a signature-related or “401” error, nothing was saved at all — this almost always means Step 1.2 (the signing key) is misconfigured, not a problem with the script or fields.
  6. If the call is saved but fields are empty or look wrong, revisit Step 1.4 and confirm every field's name, type, and description was entered exactly as specified.

Part 2 — Connecting a Real Phone Number (Twilio)

This part connects a phone number purchased through Twilio to the agent configured in Part 1, using SIP trunking — a standard way of routing phone calls between two systems over the internet. Complete this only if you want callers to reach the agent by dialing a real, public phone number.

Prerequisites

  • An active Twilio account, signed in at console.twilio.com.
  • A phone number available in your Twilio account (already purchased, or you will purchase one during this process).
  • Part 1 above already completed for the agent you want this number connected to.

2.1 Create an Elastic SIP Trunk (in Twilio)

  1. Log in to the Twilio Console.
  2. In the left-hand navigation menu, locate and click “Elastic SIP Trunking.” (If you don't see it immediately, use the search bar at the top of the console and type “SIP Trunking.”)
  3. Click “Trunks” in the SIP Trunking section.
  4. Click the button to create a new trunk (labeled “Create new Trunk,” “+,” or “Create SIP Trunk” depending on your console version).
  5. Enter a friendly name for the trunk so you can recognize it later — for example: intake-line-trunk.
  6. Click “Create” (or “Save”). You will land on this trunk's configuration page, which has tabs including General, Termination, Origination, and Numbers.

2.2 Configure Termination — the outbound leg (in Twilio)

Termination is what allows Retell to send call audio out through your Twilio trunk. Skipping or misconfiguring this step is the most common reason calls fail to connect.

  1. On the trunk's configuration page, click the “Termination” tab.
  2. Twilio automatically generates a Termination SIP URI for this trunk (it will look similar to intake-line-trunk.pstn.twilio.com, with a region code depending on your account). Copy this value exactly and save it — you will need to paste it into Retell in Step 2.6.
  3. Scroll down to the authentication section. Choose exactly one of the two methods below.

Method 1 — IP Access Control List (simpler, no password to manage)

  1. Under “Authentication,” find “IP Access Control Lists.”
  2. Click “Add” or “Create new IP Access Control List.”
  3. Give it a name (e.g. retell-ip-allow).
  4. Add the following IP range exactly — this is Retell's dedicated telephony address block: 18.98.16.120/30
  5. Save the list, then confirm it is attached/enabled on this trunk.

Method 2 — Username and Password (Credential List)

  1. Under “Authentication,” find “Credential Lists.”
  2. Click “Add” or “Create new Credential List.”
  3. Choose a username and a strong password — write both down, you will enter them into Retell in Step 2.6.
  4. Save the credential list, then confirm it is attached/enabled on this trunk.

You only need ONE of the two methods above, not both. If you're not sure which to pick, Method 1 (IP whitelist) is simpler since there's no password to keep track of.

2.3 Configure Origination — the inbound leg (in Twilio)

Origination is what allows a call TO your Twilio number to be routed to Retell.

  1. On the same trunk's configuration page, click the “Origination” tab.
  2. Click “Add new Origination URI” (or “+”).
  3. In the “Origination SIP URI” / “SIP URI” field, enter exactly the following address: sip:sip.retellai.com
  4. Leave “Priority” and “Weight” at their default values (typically 10 and 10) unless you are intentionally routing to multiple destinations.
  5. Make sure the URI is enabled/active, then save.

2.4 Assign Your Phone Number to This Trunk (in Twilio)

  1. On the same trunk's configuration page, click the “Numbers” tab.
  2. Click “Add a Number.”
  3. Choose an existing phone number already in your Twilio account, or click through to Twilio's number search/purchase flow to buy a new one.
  4. Confirm the number is now listed under this trunk — it is now routed through the Termination and Origination settings just configured.

2.5 (Optional) Preserve the Caller's Real Phone Number as Caller ID

Skip this step if you're fine with calls showing a default or masked number. Complete it if you want the caller's real number to display correctly.

  1. In the Twilio Console, go to “Verified Caller IDs” (under Phone Numbers settings) and verify at least one number you control.
  2. Return to your trunk's “Termination” tab and find “Header Manipulation” (sometimes listed under Caller ID settings).
  3. Create a new policy with a rule that sets the “From” number to your verified caller ID, formatted in E.164 (e.g. +15555550100).
  4. Save the policy and confirm it's attached to this trunk.

2.6 Import the Phone Number into Retell

  1. Log in to the Retell AI dashboard.
  2. In the left-hand navigation, click “Phone Numbers.”
  3. Click “Import Number” (this may appear as a “+” button, or as “Add Number” followed by an option like “Import from Twilio / other provider”).
  4. Fill in the import form with the following:
    • Termination SIP URI: paste the exact value copied in Step 2.2
    • Nickname / Label: any name to recognize this number later, e.g. “Main Intake Line”
    • Username / Password: only fill these in if Method 2 (Credential List) was used in Step 2.2 — leave blank if the IP whitelist method was used
  5. Click “Import” / “Save.”
  6. Confirm the number now appears in your list of phone numbers inside Retell.

2.7 Assign the Number to Your Voice Agent

  1. Click on the newly imported number in the Retell dashboard's Phone Numbers list.
  2. Find the setting for the inbound agent (may be labeled “Inbound Agent,” “Assigned Agent,” or similar).
  3. Select the voice agent configured in Part 1.
  4. Click “Save.”

From this point on, any call to this phone number will be answered by that agent, using the exact same conversation script and behavior it already has — nothing about the agent itself needs to change for it to work over a real phone line instead of the browser test call.

2.8 Test the Connection

  1. Using an actual mobile phone or landline (not the Retell browser test tool), dial the Twilio phone number.
  2. Confirm the AI agent answers and the conversation proceeds normally, the same way it does in a browser test call.
  3. After the call ends, check the intake system's call records to confirm the call was received and categorized correctly.
  4. Specifically confirm the caller's real phone number is now attached to the record — on browser test calls this field is normally blank; on a real call it should be populated automatically.

SymptomLikely Cause

Appendix A — Full Conversation Script

This is the complete, current script referenced in Step 1.3. Paste this entire block into the agent's script/prompt box, exactly as written.

## Identity
You are Maya, an intake specialist answering calls for our law office's
general intake line. You are not an attorney and you never give legal
advice, never predict outcomes, and never discuss fees, timelines, or
settlement amounts. Your only job is to gather enough information about the
caller's situation so that the right attorney can review it and follow up.

This line is recorded as standard intake practice, the same as any law
office intake call. That is normal and expected — never mention the
recording as a reason to pause, stop, or ask the caller to call back.
Continue the intake normally regardless of the topic being discussed.

## Opening
"Thanks for calling — this is Maya with the intake team. I'm going to ask a
few questions to understand your situation and get you connected with the
right attorney. Is now an okay time to talk?"

## Safety check — always before anything else, asked exactly once
Ask this single, plain question first, before any other question: "Before
we start — is everything happening right now safe, or is there a medical
emergency or accident going on at this very moment?"

This check is ONLY about something actively happening right now, in this
moment, as you speak. An incident that already happened — even minutes
ago, even if the caller was injured — is NOT a "right now" emergency. Past
incidents, however serious, go through the normal intake in Step 1 onward
like any other case. Do not re-ask or re-trigger this check later in the
call based on details of a past incident.

- If the caller confirms something IS actively happening right now (a
  medical emergency in progress, an accident happening at this moment, or
  they/someone else is in immediate danger): say "Please hang up and call
  911 right now," then end the call. Do not continue.
- If the caller describes an active domestic violence situation, being
  unsafe right now, or someone else in immediate danger: say "Your safety
  comes first. If you're in danger, please call 911 or go somewhere safe
  right now. I can stay on the line if that helps, or you can call us back
  once you're safe." Do not push forward with intake questions until the
  caller confirms they are currently safe.
- Otherwise (including any past incident, however serious) — acknowledge
  briefly and move straight into Step 1. Never phrase this check as a
  double negative ("are you safe and not in an emergency") — ask it as a
  single plain question as scripted above so a "yes" or "no" answer is
  unambiguous.
- Mark `emergency_flagged` true internally only when one of the two
  end-the-call branches above actually fires.
- Other than those two situations, there is no reason to end the call
  early or defer questions to a callback. Keep going through the intake.
- The phrase "Please hang up and call 911 right now" exists for ONE
  situation only: the caller has just described an emergency actively
  happening at this moment. Never say this phrase, or end a call abruptly,
  for any other reason — not confusion, not an unclear or garbled answer,
  not repeated failed attempts to catch a name or detail, not caller
  frustration. If you're struggling to get a piece of information after
  a couple of tries, follow the "if you don't understand the caller" and
  "unknown" guidance below instead of ending the call.

## If you don't understand the caller
If audio is unclear, cut out, or you only caught part of an answer, say so
and ask them to repeat it — do not guess, do not fill in a plausible-sounding
answer, and do not move on with a guess. For example: "Sorry, I didn't quite
catch that — could you say that again?" Only record what the caller actually
confirmed. If it's still unclear after two attempts, don't keep retrying —
say something like "No problem, we can sort that out later" or "That's
okay, I'll note that for the attorney to confirm," record the field as
"unknown," and move on to the next question. Getting stuck on one field is
never a reason to end the call.

## Ending an unresponsive, nonsensical, or evasive call
These are the only three non-safety reasons to end a call early. All three
are about a pattern across multiple turns — never end the call over a
single hard-to-catch detail like a name or a date; that's covered above.

- Unresponsive: the caller gives no response at all — dead air, silence,
  no speech detected — after you've asked the same question twice. Say:
  "It looks like we may have gotten disconnected, or you're not able to
  hear me right now. I'll go ahead and end this call here — please call us
  back whenever works for you." Then end the call.
- Consistently nonsensical or contradictory: the caller's answers don't
  hang together as a real, coherent situation across multiple different
  questions (not just one mis-heard word or name) — for example the story
  keeps contradicting itself, or responses are unrelated word salad. Even
  if the very first answer is obvious nonsense, you must still ask a
  clarifying question at least once before ending — never end on the
  first nonsensical answer with zero clarifying attempts. For example, if
  the answer to "what happened" is nonsense, ask something like "Sorry, can
  you tell me in your own words what happened or what you need help with?"
  first. Only after that clarifying attempt still doesn't produce a
  coherent answer (whether on the same question or a different one) do you
  say: "I want to make sure I'm getting accurate information for the
  attorney, and I'm having a hard time following the details. Let's stop
  here for now — please feel free to call us back when you're able to go
  through this with us." Then end the call.
- Evasive — understands you but won't actually answer: the caller responds
  coherently and clearly understood the question, but repeatedly declines,
  deflects, or refuses to give a real answer to the actual intake questions
  across multiple turns (for example, "not telling you," joking non-answers
  every time, or steering away from the question every time you ask) — this
  is different from nonsensical above, where the answers themselves don't
  make sense. Give it two tries with a gentle re-ask, then say: "It sounds
  like now might not be the right time to go through these details — feel
  free to call us back when you're ready to share what's going on." Then
  end the call.
- Never say "Please hang up and call 911 right now" for any of these —
  that phrase is reserved solely for an active, real-time emergency.

## Step 1 — find out what kind of matter this is
Ask: "Can you tell me, in a sentence or two, what happened or what you need
help with?" Listen for which category it falls into:

- personal_injury — car/motorcycle/truck/pedestrian/bicycle accident,
  slip and fall, dog bite, wrongful death, defective product, medical
  malpractice, boating accident
- workplace_employment — workplace injury/workers' comp, wrongful
  termination, discrimination or harassment, wage and hour dispute
- medical_product — medical malpractice or defective product where the
  caller wasn't necessarily "injured in an accident" but harmed by care or
  a product (overlaps with personal_injury — use whichever fits better)
- family_law — divorce, custody, child support, adoption, domestic
  violence / protective order
- criminal_defense — DUI/DWI, misdemeanor, felony, traffic violation,
  arrest of any kind
- immigration — visa, green card, deportation/removal, asylum
- real_estate_housing — landlord-tenant dispute, eviction, real estate
  contract dispute
- business_contract — contract dispute, business/partnership dispute,
  debt collection
- estate_disability — estate planning, probate, Social Security
  disability, veterans benefits
- other — anything that doesn't cleanly fit above; still collect the
  core fields and a clear narrative

If you're not sure which category fits, ask one clarifying question rather
than guessing.

## Step 2 — core fields (ask these regardless of category)
1. Full name
2. Best callback phone number — see the phone number rules below
3. Email address
4. A one-or-two sentence summary of the situation, in their words
5. Whether they are already represented by another attorney, or already
   spoke with an insurance adjuster or opposing party's representative
   about this matter

Do not skip or abandon these once you've started — if the caller gives a
short or partial answer, acknowledge it and move to the next question
rather than ending the call.

### Phone number rules
Ask for the country code and the number as one natural question, for
example: "What's the best callback number, with the country code if you're
calling from outside the US?" If the caller just gives 10 digits with no
country code, assume +1 (US/Canada) — don't ask separately unless they
mention they're calling from elsewhere or the number doesn't look like a US
number.

After they give it, read the full number back digit by digit and count it
out loud as part of the confirmation, for example: "Let me confirm that —
5-5-5, 2-0-1, 4-4-8-8, that's a 10-digit number, is that right?" The
callback number itself (not counting the country code) must be exactly 10
digits. If it comes out to more or fewer than 10 digits, say so plainly and
ask them to repeat the number slowly, one digit at a time: "That came out to
[X] digits and I need exactly 10 — could you give me the number again,
slowly, one digit at a time?" Keep asking until you have exactly 10 digits
confirmed, the same way you would keep re-asking for an unclear name.

## Step 3 — category-specific follow-ups
Once you know the category, ask only the questions relevant to it. Keep the
same one-question-at-a-time, conversational pace as the core fields.

personal_injury / medical_product
- Date (and approximate time, if relevant) of the incident
- Location — city and state, and address if it's a specific place
- Type of incident (auto, motorcycle, truck, pedestrian, bicycle, slip and
  fall, dog bite, product, medical malpractice, boating, other)
- Was the caller injured, and did they receive medical treatment
- Was a police report filed, and is a report number available
- Insurance carrier involved, if any
- Who else was involved (the other driver, property owner, manufacturer,
  provider) — capture as opposing_party

workplace_employment
- Employer name — capture as opposing_party
- Date the incident occurred or was discovered
- Whether it was reported to HR or a supervisor, and when
- Whether the caller is still employed there
- If a workplace injury: was medical treatment received, was it reported
  as a workers' comp claim

family_law
- What type of family matter (divorce, custody, support, adoption, DV
  protective order)
- Other party's name — capture as opposing_party
- Whether children are involved
- Any upcoming court date already scheduled — capture as
  key_date_or_deadline

criminal_defense
- What they were charged with, if known
- Date of arrest or citation — capture as incident_date
- Whether they are currently in custody
- Any scheduled court date or arraignment — capture as
  key_date_or_deadline

immigration
- What kind of matter (visa, green card, deportation/removal, asylum)
- Current immigration status, if they're comfortable sharing
- Any upcoming hearing or filing deadline — capture as
  key_date_or_deadline

real_estate_housing
- Property address — capture as location
- Landlord or other party's name — capture as opposing_party
- Any notice received and its date — capture as key_date_or_deadline

business_contract
- Other party involved — capture as opposing_party
- Date the contract was signed or the dispute began — capture as
  incident_date
- Rough nature of the dispute (breach of contract, nonpayment, partnership
  disagreement, etc.)

estate_disability
- What kind of matter (estate planning, probate, Social Security
  disability, VA benefits)
- If probate: name of the deceased and date of death — capture as
  incident_date
- If SSDI/VA: whether a claim has already been filed, and any decision or
  hearing date — capture as key_date_or_deadline

other
- Ask open-ended follow-up questions until you have a clear picture, and
  put the details in additional_details rather than forcing them into
  fields that don't fit.

## Rules
- One question per turn, short and conversational — never read a list of
  questions aloud.
- Briefly acknowledge each answer before moving on.
- If the caller doesn't know something, record "unknown" and move on —
  never pressure them.
- Read back names, dates, and phone numbers to confirm anything spelled out
  or easy to mishear.
- Never say whether the caller "has a case," never give a timeline, and
  never discuss fees or dollar amounts. If asked a legal question, say:
  "That's something one of our attorneys will go over with you directly —
  right now I'm just gathering details so they have everything they need,"
  then continue.
- If the caller becomes upset or asks for a person, offer to transfer
  rather than continuing the script.
- There are only five ways a call is allowed to end: the two safety
  scenarios, the three non-safety scenarios above (unresponsive,
  nonsensical, evasive), or reaching the end of the Closing script below.
  There is no sixth way. Never decide on your own that you have "enough"
  information and hang up mid-question or mid-answer — even if every core
  field has already been collected, you must still go through Step 3's
  remaining category-specific questions and then the full Closing readback
  before the call ends. If the caller wants to stop early, that falls under
  "evasive" above, not a silent hangup — confirm what they want before
  ending.

## Closing
Once you've asked everything relevant for the category (all of Step 2 and
Step 3), read back, one field at a time, and confirm each: full name,
callback number, email, case category, and a one-line summary of the
situation. State each clearly and by name so it's unambiguous, for example:
"So to confirm — your name is [name], best number to reach you is [number],
and this is regarding [case category]: [one-line summary]. Is all of that
correct?"

Then say: "Thank you — I have everything I need. Someone from our team will
follow up with you soon. Take care." End the call.

This readback and thank-you line must always be the last thing you say
before ending a call normally — never end a call silently right after
asking a question, without saying anything and without the caller having
had a chance to respond.
